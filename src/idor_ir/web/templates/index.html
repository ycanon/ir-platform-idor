            Evaluación del modelo local

            Banco de ~15 preguntas con los hechos esperados de la evidencia de este run, más el flujo de agentes en una carpeta temporal (no reemplaza el resultado de arriba). Mide hechos presentes, fechas e IPs correctas, listas completas, tácticas MITRE y tiempo. Varios modelos separados por coma se comparan en la tabla. Siempre usa el Ollama local; en CPU puede tardar 15–25 min por modelo.

            Agentes

            Modelo de lenguaje para los agentes

            Ollama en la LAN o una API comercial. Las API keys se guardan solo en la memoria del servidor (se pierden al reiniciarlo), nunca se devuelven al navegador y no se escriben en logs.

            Proveedor fuera de la red local: antes de ejecutar los agentes se pedirá autorización para enviar el contexto agregado del incidente.

              Modelo para la conversación

              El chat con los agentes puede usar el mismo proveedor y modelo de los agentes u otros distintos (p. ej. agentes con un modelo local más capaz y chat con uno más rápido, o chat con una API en la nube). Si el proveedor necesita API key o URL, ingréselas aquí: se guardan para ese proveedor (solo en memoria) y también se ven en el formulario de arriba.

                Parámetros del análisis

                El perfil del incidente se detecta del dataset en cada análisis; los valores "de respaldo" solo se usan si no se detecta ningún endpoint con ID de objeto.

                Inteligencia de amenazas · servidor MCP ti-gateway

                Las fuentes las define el servidor MCP ti-gateway; aquí se configuran sus claves (solo en memoria, o desde TI_<ID>_API_KEY; MISP pide además la URL de su instancia, interna o externa, en la columna Conexión, o TI_MISP_URL) y sus límites. Cada consulta lanza el gateway solo con las claves necesarias. Revise los términos de cada fuente: varias limitan el uso comercial.

                Las claves se envían una vez y quedan solo en memoria del servidor.
